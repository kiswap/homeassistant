# Hub split implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move the server and dashboard out of the `thermobeacon` repo into a new `homeassistant` hub repo with a plugin interface, make the thermobeacon receiver its first plugin, and reduce the `thermobeacon` repo to the Android app.

**Architecture:** A small PHP core (`core/`) routes API requests to plugins and serves plugin browser files. Each plugin lives in `plugins/<name>/` with `src/`, `web/`, and `tests/`. The dashboard core (`public/js/main.js`) loads plugin widgets with dynamic `import()`.

**Tech Stack:** PHP 8.5 (`php:8.5-cli-alpine`, `php -S`), SQLite through PDO, plain ES modules for Chromium 90, `node --test` (Node 24), Docker Compose, git.

**Spec:** `docs/specs/2026-10-31-hub-split-design.md` (in the hub repo). Executors read both.

## Global Constraints

- No PHP or JS libraries. No build step for the dashboard.
- The dashboard must work in Chromium 90, and every browser path must be relative, because nginx serves the hub under `/homeassistant/`.
- krpi runs 32-bit PHP: no integer constants above 2147483647.
- The container command keeps `-q -d display_errors=0 -d log_errors=1`.
- The thermobeacon plugin answers `POST /api/readings` and `POST /api/thermobeacon/readings` the same way. The answers stay as today: 200 with `stored`/`duplicates`/`ignored`/`rejected`, 401, 400, 405, 413, and 503.
- The thermobeacon SQLite file keeps its tables `readings` and `meta` unchanged.
- The `localStorage` key `thermobeacon.prefs.v1` keeps its name.
- Never remove a test to make a suite pass. Never delete files or branches. Copy from `thermobeacon/server/`, do not move.
- Git commits in both repos use `git -c user.name=kiswap -c user.email=kiswap@gmail.com commit`, and each message ends with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Error log lines start with `homeassistant: ` (core) or `thermobeacon: ` (plugin).

Test commands, run from `tab3/homeassistant/`:

- PHP: `docker run --rm -u $(id -u):$(id -g) -v "$PWD:/app" -w /app php:8.5-cli-alpine php tests/run.php`
- JS: `npm test`
- Smoke: `SMOKE_PORT=18090 bash tests/smoke.sh`

## Review Focus

- A plugin `.js` file served with the wrong `Content-Type`. Chromium refuses ES modules that are not served as JavaScript, so the dashboard would stay empty. Task 4 tests the header.
- A settings file naming a plugin whose folder or class is missing. The API should answer 500 with a log line that names the plugin, and the dashboard should show its "Cannot reach the server" retry text, not a blank page. Task 2 tests it.
- A widget type whose plugin is not enabled, or a type with no widget file. The widget should become a placeholder that says "unknown widget: <type>", as today. Task 5 tests it.
- Global PHP test helper names that collide once core and plugin tests load into one runner, for example `call` or `body`. The runner should fail loudly, not skip tests. Task 3 checks the test count.
- An old krpi `settings.json` with extra keys (`home_networks`, `basic_auth`) or without `stale_after_seconds` and `refresh_seconds`. The conversion should drop the extra keys and fill in the defaults 600 and 60. Task 6 tests it.
